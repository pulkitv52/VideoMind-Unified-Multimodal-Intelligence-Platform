# Small video collection for local development

This pack exercises VideoMind's existing authenticated file intake on the CPU-only laptop. It adds 30 videos across three collections, without enabling extraction, embeddings, search or in-app media playback. Click a filename to download its stored MP4. Status **validated, not indexed** is expected.

| Collection | Videos | Coverage |
| --- | ---: | --- |
| CAVIAR - Stores and lobby | 15 | Shop entry/exit, waiting, browsing, walking, meetings, staged falls and chase |
| UR Fall - Falls and daily activities | 10 | Five staged falls and five daily activities, camera0 RGB |
| Roadscapes - Day and night driving | 5 | Three daytime and two nighttime dashcam sequences |

UR Fall provides staged research recordings, not real hospital CCTV. Selected sequences are fall01–05 and ADL01–03/24/28; the last two are shorter activity clips to keep downloads bounded. Roadscapes descriptions were generated by Gemini 1.5 Pro and are explicitly unverified by the publisher. Sequence names and selection hints are not independently reviewed event labels. This sample pack is not a balanced classification, retrieval, clinical or safety benchmark.

## Originals, derivatives and terms

Upstream files and annotations remain immutable under `.local/datasets/video30/originals/`. CAVIAR MPEG and UR Fall PNG ZIP files cannot be uploaded directly through the current supported-format intake, so preparation creates video-only MP4 derivatives. All three datasets use the same conversion: libx264, CRF 23, maximum width 640, two encoder threads, no B frames. Original audio, if present, remains in the upstream file and is omitted from the MP4 preview. Filenames explicitly end in `__derived.mp4`.

Every decoded frame is mapped to its upstream frame and PTS/time base or PNG archive member/frame number/synchronization timestamp. UR Fall uses actual sequence-relative milliseconds in the publisher CSV, including irregular frame intervals. Conversion subtracts the first timestamp for MP4 playback; the mapping retains the upstream timestamp. Seven CAVIAR lobby files contain duplicate source PTS values. For those duplicates only, the playback timestamp advances by one 1/90000-second tick; the mapping retains the unchanged source PTS and records each adjustment. Backwards timestamps are rejected. The script verifies decoded derivative frame counts and timing against the explicit playback mapping to within 1 ms. It does not drop, interpolate or trim frames.

The current intake stores these uploaded MP4s as its original uploaded bytes. It does not yet expose upstream derivative provenance or per-frame mappings in the product. The manifest and attribution files document that distinction until the later media/evidence phase.

Licenses and credits are recorded per clip in `evaluation/manifests/video30.json` and each collection's uploaded attribution Markdown. CAVIAR declares CC BY-SA without a version on its dataset page; retain that ambiguity. UR Fall declares CC BY-NC-SA 4.0, and Roadscapes declares CC BY-NC 4.0. Keep this pack for noncommercial local development, preserve attribution and applicable share-alike terms, and review source terms before redistribution or commercial use. Roadscapes publisher licensing does not independently establish ownership of every underlying recording.

Sources: [CAVIAR](https://groups.inf.ed.ac.uk/vision/DATASETS/CAVIAR/CAVIARDATA1/), [UR Fall](https://fenix.ur.edu.pl/mkepski/ds/uf.html), [Roadscapes](https://huggingface.co/datasets/vijpandaturtle/roadscapes-video). Roadscapes downloads are pinned to publisher revision `be701e244d6d4a83b83723db4142463413484899` and checked against publisher SHA-256 hashes. Commons road clips were considered but not imported after publisher rate limiting; the five Roadscapes clips replace that selection.

## Reproduce

Run from the repository root, with the feasibility Python environment installed and the local application running:

```bash
backend/.venv/bin/python -m evaluation.datasets.video_pack fetch
backend/.venv/bin/python -m evaluation.datasets.video_pack fetch-roads
backend/.venv/bin/python -m evaluation.datasets.video_pack merge
backend/.venv/bin/python -m evaluation.datasets.video_pack convert
backend/.venv/bin/python scripts/import_video_pack.py
```

The first two commands require network access. Run commands sequentially: fetch and conversion both update the manifest. Downloads use two university requests concurrently and one Roadscapes request at a time, bounded file sizes and explicit rate-limit handling. Conversion streams frames instead of loading full clips in RAM; no inference model or GPU is used.

Reruns reuse local originals and derivatives; the importer verifies recorded hashes before uploading and reuses named collections. Identical filename/content uploads are no-ops. Upstream originals, PNG archives and mapping JSON are not bulk-uploaded into supported-format collections. Each collection gets one attribution Markdown file in addition to its videos.

`evaluation/reports/video30-intake.json` records completed intake verification: terminal stored jobs, authenticated original-download SHA-256 round trips and one repeated-upload no-op per collection. The elapsed import value excludes network download and conversion. `evaluation/tests/test_video_pack.py` checks variable timing, RGB archive-to-timestamp mapping and rejection/cleanup of non-increasing encoder timestamps and explicit source-duplicate playback repair. These checks do not measure semantic retrieval quality.

The next functional development step remains document extraction/evidence viewing, then media processing and embeddings/search under the phased implementation plan. Adding a dataset does not complete those phases.

## Completed local check, 18 October 2026

All 30 videos and three attribution files reached stored/validated status. Authenticated downloads matched SHA-256 for all 33 files, and a repeated video upload in each collection was a no-op. The converter tests passed: four checks covering variable frame timing, RGB/CSV mapping, duplicate source timestamp repair and encoder rejection/cleanup. All 17,175 decoded frames have mapping entries. Seven CAVIAR clips required 22 duplicate-PTS playback adjustments.

Upstream media/archives total 684,476,404 bytes (652.77 MiB); the uploaded MP4s total 53,086,890 bytes (50.63 MiB). Originals, annotations and mapping sidecars use additional host disk space. The final import/verification pass took 15.73 seconds and reused 30 existing files while uploading two new videos and one attribution file. It excludes the earlier imports, network transfers and conversion and is not a throughput benchmark. No GPU or embedding model was used.

The browser showed collection totals of 16 CAVIAR files, 11 UR Fall files and six Roadscapes files (each includes one attribution document), with validated/not-indexed status. UI evidence: `evaluation/reports/video30-ui.jpg`.
